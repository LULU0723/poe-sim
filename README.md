# 創世之樹 策略最佳化模擬器 (poe-sim)

針對 Path of Exile **創世之樹（Genesis Tree）** 機制的純前端規劃工具。依照 3.29 的 16 點上限排出最佳天賦組合，即時計算每條詞綴在當前配置下的出現機率，並用暴力搜尋演算法替你找出評分最高的路徑。

> **3.29 資料狀態：** 已套用裝備分支 16 點上限、額外裝備小天賦 50% → 25%，以及指定詞綴類型大天賦 500% → 300%。官方未公開「內建詞綴階級評分」、「高階基底傾向」與「內建額外裝備機率」的精確新數值，因此目前不對這三項隱藏參數進行推測。

> 適用對象：想拚特定詞綴組合、不想盲目試錯天賦點的玩家。

---

## ✨ 功能特色

- **🗺️ 雙視圖天賦樹**
  - 視覺地圖模式：依照原圖座標排列節點，可縮放（50%–300%）
  - 結構清單模式：依父子關係階層展開，方便看路徑
  - 座標校準模式：拖曳節點微調位置，自動存到 localStorage

- **🧮 即時機率計算**
  - 根據已啟用節點的 `mods`（如 `+300% 抗性詞綴`、`-60% 防禦詞綴`）動態調整每條詞綴的權重
  - 前綴 / 後綴分開計算佔比
  - 標籤命中採加總方式（與遊戲內 increased/reduced 相同邏輯，待驗證）

- **🎯 三類詞綴標記**
  - `🎯 目標詞`：希望出現的詞綴（評分 +1000 × 機率）
  - `✅ 可接受`：次要詞綴（評分 +100 × 機率）
  - `❌ 不想要`：污染詞綴（評分 -1000 × 機率）

- **🪄 一鍵最佳化**
  - 暴力枚舉 A/B/C 棄絕系列 × L/M/N 奉獻系列 × D/E/F/K 功能節點偏好
  - 自動填滿剩餘點數（保留玩家手動點過的工具節點）
  - 結束後給出警告：目標詞機率偏低、點數不足無法納入偏好節點

- **📚 內建詞綴庫**
  8 個裝備類別 × 屬性子分類，共 30+ 套官方數據預設：
  頭盔 / 胸甲 / 手套 / 鞋子 / 護身符 / 戒指 / 腰帶 / 盾牌（含力/敏/智/力敏/力智/敏智）/ 珠寶（赤紅/鈷藍/翠綠）

- **🧭 策略顧問**
  針對 6 種屬性底材（純力 / 純敏 / 純智 / 力敏 / 力智 / 敏智）推薦：
  - 💰 **防污染法**（CP）：低點數，切斷稀釋來源
  - 🔥 **極限機率**（Max）：高點數，雙向強化目標屬性

- **📂 個人預設庫**
  - 匯入單一 JSON 或批次匯入多個 JSON
  - 自動存到 localStorage，下次開啟即可載入
  - 支援匯出當前詞綴設定備份

## 📖 使用流程

1. **選裝備類型與屬性**（右上角下拉選單）
   例如：`🛡️ 盾牌` → `💪 純力 (護甲)`

2. **點「讀取詞綴與策略」**
   - 自動載入對應的詞綴庫
   - 自動切換天賦樹基底鎖定節點（如盾牌會自動點上 `G1`）
   - 顯示策略顧問面板（僅防具底材會顯示）

3. **標記目標詞綴**
   下拉選單把想要的詞綴改成 `🎯 目標詞`、不想要的改成 `❌ 不想要`

4. **（可選）設定功能節點偏好**
   D / E / F / K 四個工具節點，依需求選「不需要 / 普通 / 重要」

5. **點「最佳化」**
   等個 0.5–1 秒，演算法會自動排出最高評分的天賦組合

6. **檢視結果**
   - 看每條詞綴的當前機率
   - 看警告提示（機率過低、點數不足等）
   - 不滿意可手動微調節點、再次最佳化

## 📄 詞綴 JSON 格式

`public/presets/*.json` 採用陣列格式：

```json
[
  {
    "id": "1775723800001",
    "type": "prefix",
    "name": "# 最大生命",
    "tags": "生命",
    "baseWeight": 11000,
    "category": "neutral"
  }
]
```

| 欄位 | 說明 |
|------|------|
| `id` | 唯一識別碼（字串）|
| `type` | `prefix` 或 `suffix` |
| `name` | 詞綴名稱，`#` 代表數值佔位符 |
| `tags` | 用逗號或頓號分隔的標籤，例如 `元素、火焰、抗性` |
| `baseWeight` | 基礎權重（整數）|
| `category` | `neutral` / `target` / `acceptable` / `unwanted` |

**支援的標籤**（會被節點 `mods` 影響）：
`生命` `魔力` `防禦` `屬性` `抗性` `速度` `施法` `攻擊` `暴擊` `閃電` `冰冷` `火焰` `物理` `混沌` `力量` `敏捷` `智力`

匯入個人預設時也接受包裝格式：
```json
{ "affixes": [ /* 同上 */ ] }
```

## 🧪 底層假設（重要）

大家點創世之樹時，體感常像是按下去全部純隨機，不知道官方底層怎麼算的。本工具的機率計算建立在以下假設上——**這些多為尚未經官方證實的推測**，若遊戲實際機制不同，模擬結果會有偏差，請以遊戲為準。（App 內也有同樣的「底層假設說明」折疊面板。）

### 【已確認】基底的專屬詞綴池無法突破

每個基底有自己專屬的詞綴池，例如純力（護甲）基底天生洗不出法術壓抑。創世之樹本質上是「權重放大器」，不像精髓可以強行點出不屬於該基底的詞綴——基礎權重為 0 的詞綴，即使點了 +300%，`0 × 4` 依然是 `0`。
因此匯入 JSON 詞綴庫時，請確保輸入的詞綴是該基底原本就洗得出來的。

### 假設一：減益節點相加、權重可被壓到 0

減益節點採相加邏輯。某條同時帶「物理」與「攻擊」標籤的詞綴，若同時點了 −60% 物理與 −60% 攻擊：

```
倍率 = 1（基數） − 0.6 − 0.6 = −0.2 →（下限 0）→ 歸零
```

該詞綴權重被壓到 0，等同從詞綴池中消失。
> **待驗證**：官方是「相加可歸零」還是「獨立相乘（1 × 0.4 × 0.4 = 0.16，剩 16%）」？若你點了雙 −60% 卻仍洗出該詞綴，歡迎回報。

### 假設二：多標籤詞綴的加成為相加

一條詞綴同時帶多個受天賦影響的標籤時，倍率相加。某詞綴帶「火焰」與「抗性」，並點了 +300% 火焰與 +300% 抗性：

```
倍率 = 1（基數） + 3.0 + 3.0 = 7 倍
```

這裡指權重倍率，最終機率還要看池中所有詞綴的權重總和。
> **待驗證**：官方遇到多標籤時是相加（11×）、相乘（6 × 6 = 36×），還是只取最高值（6×）？（依假設一的實測反推，目前傾向「相加」。）

### 假設三：珠寶基底是否受詞綴標籤影響掉落

防具有明確屬性需求，可透過 −85% 智力等節點排除不想要的基底類型。但珠寶沒有屬性需求，三種基底（赤紅／鈷藍／翠綠）各有不同的詞綴池。
> **待驗證**：天賦樹的標籤加成是否會間接影響珠寶基底的掉落權重，還是三種珠寶基底完全獨立於詞綴標籤。

### 假設四：各基底初始掉落權重均等

假設純力、純敏、純智、力敏、力智、敏智 6 種防具基底的初始出現機率完全一樣，再由 g 節點（×0.15 稀釋 / ×4 強化）調整。策略顧問即基於此推薦「砍斷稀釋來源」。
> **待驗證**：遊戲底層是否有隱藏權重差異（例如複合基底是否天生比純屬性基底更稀有）。

### 假設五：創世之樹與一般掉落共用基礎權重表

JSON 詞綴的基礎權重完全參考 PoEDB 的權重，假設創世之樹直接套用同一套表。
> **待驗證**：官方是否為創世之樹另外寫了專屬或修改過的詞綴池／權重表。

### 假設六：面板顯示為單次獨立抽取機率

面板上的百分比代表「系統現在抽一條前綴／後綴時，抽中該詞綴的機率」。本工具只計算單次抽取機率，**不模擬**完整的多詞綴生成流程（同群組互斥、前後綴數量分配等），因此實際成品上看到某詞綴的機率通常會高於此數字。
